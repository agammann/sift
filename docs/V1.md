# Sift 1.0 contract

[Back to the README](../README.md)

Sift 1.0 is a local documentation collector for one user. A newcomer can extract the release, create a collection, refresh a supported public source, inspect its retained text, and search it. A developer can build the source and connect an MCP client to that same persistent workspace. No account or model key is required.

## Supported sources and delivery

| Input or environment                                    | Support in 1.0                                                                                |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Public UTF-8 HTML, rendered by the server               | Supported within one source's exact origin and allowed path prefixes                          |
| Ordinary HTML documentation with article/main text      | Preferred; source URL, retained revision and collection version label accompany retrieval     |
| Simple HTML without an article/main region              | Body fallback; inspect extraction warnings                                                    |
| HTTP redirects                                          | Supported only when the destination remains within the configured public origin/path boundary |
| JavaScript-only applications, PDFs, authenticated pages | Unsupported; Sift does not render, parse or sign in for these                                 |
| Private or reserved network destinations                | Rejected; no production bypass switch                                                         |
| Windows, macOS and Linux                                | Node 24.15 or newer within Node 24; release automation verifies Node 24.19.0                  |
| npm registry                                            | No registry package; install the local release archive or use its extracted CLI               |
| Remote/cloud MCP                                        | Unsupported; five read-only tools over local stdio only                                       |

Collection limits are explicit: 1–500 pages, depth 0–6, at most two concurrent requests, and 2–20 successful revisions retained per source. Refresh is manual. Start with one page before increasing those budgets. There is no automatic time-based record pruning; monitor your local disk and back up collections you want to keep.

## Stable interfaces

The 1.x line preserves CLI command names (`start`, `mcp`, `doctor`, `backup`, `restore`, `version`), database schema compatibility, and the five documented [MCP tools](MCP.md#tool-contract). Collection IDs and persisted revision IDs remain usable across an additive upgrade. MCP keeps its `{ok:true,data:...}` / `{ok:false,error:{code,message}}` envelope and explicit collection allowlist. Additional optional output fields may be added; clients should read the fields they need rather than reject every unknown output property.

The loopback management HTTP routes and UI component internals are application internals, not a public integration SDK. Use MCP for read-only integration. Documentation contents remain untrusted source material, not instructions for an assistant to execute.

Search is lexical AND matching, not a model answer or a guarantee that a page is current. Compare the quoted passage with its source URL, collection version label, retained revision and check time. A failed refresh keeps prior successful content and records the failed check. Confirmed unavailable pages leave current search while retained revisions remain readable until retention expires. A source or collection deletion permanently removes its content/history; back up before deleting.

## Upgrade from 0.1.2

No database schema change is introduced by 1.0. Stop management and MCP clients, create a verified [backup](OPERATIONS.md#backup-and-restore), and extract 1.0 into a new folder. Run the new CLI with the same explicit database path, check `version` and `doctor`, then reopen a collection and perform an MCP search. Copy a fresh Connect configuration when the executable path changes. Keep the old executable and verified backup until this check succeeds; do not overwrite a live database or manually change its schema version.

Sift's own code and release package are MIT licensed. [Third party notices](../THIRD_PARTY_NOTICES.md) preserve the dependency licenses. A checksum proves the downloaded bytes match the released artifact; it is not a promise that future rebuilds have identical bytes.

## Initial release stopping point

The 1.0 release requires a clean frozen source installation and build; passing existing collection, refresh, recovery and stdio MCP checks; a fresh extracted/package consumer that does not depend on source-checkout modules; a browser first-collection walkthrough; and a published immutable archive/checksum tied to the checked commit. Cross-platform jobs must pass before publication. Dependency maintenance, new source formats and additional assistant hosts continue after this bounded release.
